# Техническое задание: Writing Agent (Агент написания контента)

## 1. Назначение
Writing Agent отвечает за генерацию черновика публикации для LinkedIn на основе выбранной темы, стратегии подачи (формата) и настроек стиля автора.

## 2. Входные данные (Payload задачи)
Агент принимает тему, выбранную стратегию и полный профиль автора:
```json
{
  "runId": "uuid-string",
  "stage": "writing",
  "attempt": 1,
  "payload": {
    "topic": {
      "title": "Рост интереса к AI-агентам в backend-разработке",
      "summary": "Развернутое описание сути тренда..."
    },
    "strategy": {
      "format": "tutorial", // story, opinion, case_study, etc.
      "target_audience": "Senior Backend Developers",
      "core_idea": "Показать, как внедрение AI-агентов сокращает время написания boilerplate-кода"
    },
    "authorProfile": {
      "topics": ["Node.js", "AI", "Backend"],
      "forbidden_words": ["crypto"],
      "cta_style": "Задайте открытый вопрос в конце для вовлечения",
      "use_emoji": true,
      "tone": "профессиональный, но доступный, без лишней "воды""
    }
  },
  "extraInstructions": "Сделай больший упор на безопасность данных при работе с LLM" // опциональные доработки от Open Claw
}
```

## 3. Выходные данные (WritingOutput)
Результат валидируется Zod-схемой `WritingOutputSchema`:
```json
{
  "text": "Полный текст публикации с форматированием (абзацы, списки, если применимо)...",
  "hook": "Первая цепляющая строчка (Hook), призванная заставить пользователя нажать 'See more'",
  "cta": "Призыв к действию в конце поста"
}
```

## 4. Логика работы
1. **Trigger**: Получение задачи из очереди `QueueName.WRITING`.
2. **Context Preparation**:
   - Сбор контекста (тема, формат подачи, аудитория, ключевая идея).
   - Применение стилевых ограничений автора (тон, смайлы, запрет определенных фраз).
   - Учет `extraInstructions` от Open Claw (если это повторная итерация после ревью).
3. **LLM Generation**:
   - Генерация контента. Используются системные инструкции с примерами хороших LinkedIn-публикаций.
   - Разделение текста на Hook (крючок), Body (основная часть) и CTA (призыв к действию).
4. **Validation**:
   - Проверка структуры ответа.
   - Базовая валидация на наличие запрещенных слов на клиенте перед отправкой ответа.
5. **Publish**: Отправка события `completed` в очередь оркестратора.
