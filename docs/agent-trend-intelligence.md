# Техническое задание: Trend Intelligence Agent (Агент сбора трендов)

## 1. Назначение
Trend Intelligence Agent отвечает за сбор актуальных тем из открытых источников, их фильтрацию, группировку и ранжирование с помощью LLM для последующего использования в пайплайне генерации контента.

## 2. Источники данных (без API ключей)
Для MVP будут использоваться следующие бесплатные и открытые источники:
* **Hacker News**: Топ-30 историй через Firebase API (`https://hacker-news.firebaseio.com/v0/topstories.json`).
* **GitHub Trending**: Популярные IT-репозитории за день (парсинг `https://github.com/trending` или публичный API-зеркало).
* **Dev.to**: Статьи с высоким рейтингом / rising по ключевым тегам (например: `node`, `javascript`, `ai`, `webdev`) через `https://dev.to/api/articles`.
* **Reddit**: Популярные посты из профильных сабреддитов (`r/node`, `r/programming`, `r/webdev`, `r/artificial`) через их публичные `.json` фиды (например, `https://www.reddit.com/r/node/hot.json`).

## 3. Контракты данных

### Входные данные (Payload задачи)
Агент принимает задачу из общей очереди BullMQ.
```json
{
  "runId": "uuid-string",
  "stage": "trend",
  "attempt": 1,
  "payload": {
    "topics_limit": 5 // Максимальное количество трендов на выходе (по умолчанию 5)
  },
  "extraInstructions": "optional string with guidance"
}
```

### Выходные данные (TrendAgentOutput)
Результат валидируется Zod-схемой `TrendAgentOutputSchema` и отправляется в `eventsQueue`:
```json
{
  "items": [
    {
      "title": "Название тренда/темы (короткое и емкое)",
      "summary": "Развернутое описание сути тренда, почему он важен и какие ключевые моменты стоит осветить.",
      "score": 85, // Оценка хайпа/актуальности от 0 до 100
      "keywords": ["ai", "agents", "typescript"],
      "sources": [
        "https://github.com/example/repo",
        "https://news.ycombinator.com/item?id=123"
      ],
      "published_at": "2026-06-30T12:00:00Z" // Опционально
    }
  ]
}
```

## 4. Логика работы агента
1. **Trigger**: Получение задачи из очереди `QueueName.TREND`.
2. **Fetch**: Параллельный опрос всех 4-х источников данных (GitHub, Hacker News, Dev.to, Reddit) с ограничением по времени (timeout).
3. **Format**: Формирование сводного текстового отчета со всеми собранными статьями, репозиториями и заголовками.
4. **LLM Synthesis**:
   - Отправка отчета в `AiClient` (с использованием `OPENROUTER_API_KEY` / `GROQ_API_KEY`).
   - Использование системного промпта, который просит модель сгруппировать разрозненные посты в осмысленные тренды (например, объединить 3 поста про новые фичи Node.js в один тренд).
   - Инструкция для LLM вернуть строго JSON-структуру, соответствующую `TrendAgentOutputSchema`.
5. **Validation**: Валидация ответа LLM с помощью Zod. Если модель вернула некорректный JSON, выполняется повторный запрос (self-correction) или кидается ошибка для перезапуска задачи (retry).
6. **Publish**: Отправка события `completed` с полученным результатом в очередь событий `eventsQueue`.

## 5. Обработка ошибок и отказоустойчивость
* **Таймауты на сетевые запросы**: Каждый фетчер должен иметь таймаут (например, 5-8 секунд), чтобы зависший сайт не блокировал работу агента. При ошибке фетчера его результат просто игнорируется, а логика продолжается на основе остальных источников.
* **Резервный LLM-провайдер**: При ошибке квоты или лимитов (429/402) у OpenRouter, `AiClient` автоматически переключает вызов на Groq.
