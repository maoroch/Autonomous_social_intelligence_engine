# Technical Specification & Handover to Jules

Привет, Джулс! Тебе передаётся проект **LinkedIn AI Content Pipeline** — многоагентная система автоматического сбора трендов, написания публикаций и подготовки каруселей слайдов для LinkedIn.

Ниже приведена структура проекта, текущий статус реализации и задачи, которые нужно реализовать за эту ночь.

---

## 1. Контекст и Архитектура проекта

Система построена по принципу микросервисной архитектуры на базе Node.js, TypeScript, Docker Compose, Redis (BullMQ для очередей задач) и MongoDB:
* **Базовая библиотека (`shared-lib`):** Содержит общие схемы Zod, хелперы очередей BullMQ, соединение с MongoDB и единый AI-клиент (`AiClient`) с автоматическим фолбеком OpenRouter -> Groq.
* **Оркестратор (`openclaw`):** Управляет шагами пайплайна, пересылает события и контролирует жизненный цикл прогона.
* **Микросервисы-агенты:**
  * `agent-trend-intelligence` — сбор данных (HackerNews, Reddit, GitHub, Dev.to, SearXNG LinkedIn) и LLM-синтез трендов.
  * `agent-positioning` — фильтрация трендов по интересам и стоп-словам автора.
  * `agent-content-strategy` — определение целевой аудитории, формата и идеи поста.
  * `agent-writing` — написание текста публикации (Hook, Body, CTA).
  * `agent-design` — генерация структуры слайд-дека для карусели (заголовки, буллиты, футер, цвет).
  * `agent-seo` — аудит поста, выставление SEO-оценки и списка доработок.
* **Панель управления (`web-dashboard`):** Интерактивный интерфейс Next.js для мониторинга, аналитики, ручного запуска и инлайн-редактирования.

---

## 2. Что уже полностью реализовано и протестировано

1. **Все 6 AI-агентов:** Настроены, имеют корректные промпты и валидацию выходных схем Zod.
2. **Open Claw Quality Loop:** Если SEO-оценка сгенерированного поста `< 80`, оркестратор автоматически возвращает прогон на шаг `WRITING` (до 2 раз), прикрепляя к задаче рекомендации по доработке (`extraInstructions`).
3. **Глобальный троттлинг LLM (Rate Limiting):** В `AiClient` встроен распределенный лимитер скользящего окна в Redis (по умолчанию 5 запросов в минуту). При превышении лимита агент засыпает и ждет освобождения слота в очереди Redis, предотвращая падения по ошибке `429`.
4. **Поиск по LinkedIn через SearXNG:** В агенте трендов реализован сборщик LinkedIn-трендов через API SearXNG.
5. **5-часовой автоматический планировщик:** Встроен в оркестратор OpenClaw через BullMQ Repeatable Jobs.
6. **Инлайн-редактор контента (Human-in-the-loop):** На странице детального просмотра `/runs/[runId]` все поля поста и слайдов карусели становятся редактируемыми `input`/`textarea` в режиме `awaiting_approval`. Правки сохраняются по кнопке или автоматически при аппруве.

## 3. Задачи для реализации (Задачи для Джулса)

Ниже перечислены задачи, которые необходимо реализовать для расширения системы:

### Задача 3.1: LinkedIn Auto-Publishing Agent (Публикация)
Добавить автоматическую публикацию утвержденных постов:
1. Создать новую очередь `queue-publishing` и агента `services/agent-publishing` (либо реализовать воркер прямо внутри `openclaw`).
2. В файле [approval.ts](file:///Users/ilassalimov/Projects/linkedin-ai-pipeline/services/openclaw/src/validators/approval.ts) в обработчике `runs/:runId/approve` вместо простого перевода статуса в `APPROVED` отправлять задачу в очередь публикации.
3. Агент публикации должен принимать текст поста и путь к сгенерированному PNG-документу, после чего через LinkedIn API (или используя Puppeteer/Playwright под аккаунтом автора) совершать публикацию.

### Задача 3.2: PNG Generator для каруселей (Carousel PNG Renderer)
Реализовать преобразование структуры слайдов из JSON в готовый PNG-документ:
1. Написать утилиту или микросервис (например, используя библиотеку `canvas`, `PNG-lib` или Puppeteer для печати HTML в PNG).
2. На основе структуры слайдов (заголовок, буллиты, футер) и цвета (`accent_color`) рендерить квадратные слайды и склеивать их в PNG.
3. Сохранять сгенерированный PNG-файл на сервере / в MongoDB (`gridfs`) и возвращать его URL на дашборд, чтобы пользователь мог скачать его.

### Задача 3.3: Панель управления профилями авторов (Multi-Author Profiles UI)
Обеспечить поддержку нескольких авторов:
1. Создать коллекцию `author_profiles` в MongoDB. Перенести туда настройки `topics`, `forbidden_words`, `cta_style`, `tone` и `color_schema`.
2. Создать на Next.js дашборде страницу `/profiles` для добавления, просмотра и редактирования настроек профиля.
3. В форме быстрого запуска пайплайна на главной странице добавить выпадающий список (Select) для выбора автора, под профиль которого генерируется контент.
