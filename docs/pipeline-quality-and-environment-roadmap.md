# Дорожная карта развития: Качество генерации контента и Изоляция окружений (DEV / PROD)

В данном документе зафиксированы плановые архитектурные улучшения для проекта **LinkedIn & Multi-Platform AI Content Pipeline**, направленные на максимальное повышение качества генерации постов и обеспечения стабильности производственной среды компании.

---

## 🎯 ЧАСТЬ 1. Повышение качества контента (Agent-Writing Quality Roadmap)

Фиксированные контентные рубрики (**Content Pillars**) уже устранили хаос и дали системность. Следующий ключевой шаг — сделать **`agent-writing`** основным двигателем качества всей мультиарендной системы (так как дизайн-агент и мультипостинг зависят от глубины текста).

### 1.1. Многоэтапная генерация (Chain-of-Thought Pipeline) внутри Writing Agent
Переход от 1-step вызова LLM к 3-этапному внутреннему сценарию генерации:
1. **Этап 1: Технический сценарий & Проблема (Pain-Point Spec)**
   - Определение целевой B2B-проблемы и нормативных требований (21 CFR Part 11, GxP, ISO 17025, GDP).
   - Выбор конкретного продуктового решения (например: *Testo Saveris 1*, *testo 190 T3/T4 CFR*, *testo 174T/175H1*, *Testo Industrial Services*).
2. **Этап 2: Экспертный B2B-копирайтинг & Заголовок (Hook Engine)**
   - Написание поста по проверенным B2B-структурам (*Разрушение мифов*, *Чек-лист готовности к аудиту*, *PAS — Problem-Agitate-Solution*).
   - Формирование емкого заголовка с обязательной эмоциональной или экспертной привязкой.
3. **Этап 3: Слайд-архитектор (Design Handoff)**
   - Автоматическое деление поста на тезисные блоки для слайдов карусели.
   - Каждая карточка получает **1 четкую мысль**, **конкретную характеристику/прибор** и метку иллюстрации.

### 1.2. Матрица продуктов и привязка к рубрикам (Product Grounding)
Жесткая передача матрицы решений в промпт в зависимости от `contentPillarId`:
- **`pharma-audit-ready`** $\rightarrow$ Фокус на *Testo Saveris 1*, ПО *Testo Saveris CFR* (21 CFR Part 11, Audit Trail), калибровка *Testo Industrial Services*.
- **`pharma-cold-chain-story`** $\rightarrow$ Фокус на *testo 174T*, *testo 175H1*, *Testo Saveris 2* (мониторинг складов и холодовой цепи).
- **`pharma-compliance-explained`** $\rightarrow$ Фокус на *testo 190 T3/T4 CFR* (валидация автоклавов, сушильных шкафов и лиофилизации).

### 1.3. Изолированные эталоны (Pillar-Isolated Golden Datasets)
- Пополнение коллекции `golden_datasets` 3–5 образцовыми авторскими B2B-постами для каждой рубрики.
- Использование подборки Few-Shot примеров строго по фильтру `{ pillarId, platform }` без cross-rubric смешивания.

### 1.4. Внутренний Self-Correction перед версткой
- Автоматическая проверка сгенерированного ответа:
  - Наличие упоминания конкретных моделей/стандартов в тексте.
  - Проверка эвристики на отсутствие «водянистых» бытовых формулировок.
- При обнаружении недостатков — автоматический внутренний допрос/доработка (Refinement Prompt) перед отправкой в `agent-design`.

## 🛡️ ЧАСТЬ 2. Изоляция окружений (DEV / PROD Architecture)

Для исключения ситуаций, когда эксперименты с промптами или кодом ломают генерацию рабочих постов фирмы, внедряется строгое разделение сред.

### 2.1. Ветвление в Git
- **`main` (Production):** Содержит только протестированный, 100% стабильный код. Коммиты попадают сюда только после успешного тестирования.
- **`dev` (Development):** Песочница для экспериментов с промптами, логикой агентов и версткой слайдов.

### 2.2. Изоляция Docker Compose

#### 🟢 PROD (Рабочая среда компании)
- **Запуск:** `docker compose -p linkedin-prod up -d`
- **Порт дашборда:** `http://localhost:3000` (или домен/IP компании)
- **База данных:** `linkedin_pipeline_prod`
- **Модель LLM:** `openai/gpt-oss-120b` (PROD качество)
- **Режим:** Стабильные фоновые контейнеры без горячей перезагрузки при экспериментах.

#### 🟡 DEV (Экспериментальная среда разработки)
- **Запуск:** `docker compose -p linkedin-dev -f docker-compose.dev.yml up -d`
- **Порт дашборда:** `http://localhost:3001`
- **База данных:** `linkedin_pipeline_dev`
- **Модель LLM:** `llama-3.1-8b-instant` / OpenRouter (быстрые дешевые модели для тестов)
- **Режим:** Включен Hot-Reload и монтирование исходного кода для моментального тестирования.

### 2.3. Отказоустойчивость для экстренных постов (Safe Fallback)
1. **Ручной редактор в Дашборде:** При любых внешних сбоях LLM-провайдеров пользователь может отредактировать текст напрямую в интерфейсе и моментально сгенерировать слайды.
2. **Кнопки повтора (`Retry / Restart`):** Позволяют перезапустить упавший этап в один клик без пересборки системы.
