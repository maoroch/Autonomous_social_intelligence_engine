# Техническое задание: SEO Agent (Агент оптимизации и проверки)

## 1. Назначение
SEO Agent выполняет финальный аудит сгенерированного текста публикации. Он оценивает читаемость, цепляющий заголовок (hook), наличие призыва к действию (CTA), длину поста для LinkedIn и выдает числовую оценку вместе с рекомендациями по улучшению.

## 2. Входные данные (Payload задачи)
Агент принимает сгенерированный текст и метаданные:
```json
{
  "runId": "uuid-string",
  "stage": "seo",
  "attempt": 1,
  "payload": {
    "post": {
      "text": "Полный текст LinkedIn публикации...",
      "hook": "Первая строчка...",
      "cta": "Призыв к действию..."
    }
  }
}
```

## 3. Выходные данные (SeoOutput)
Результат валидируется Zod-схемой `SeoOutputSchema`:
```json
{
  "score": 86, // Оценка качества текста от 0 до 100
  "recommendations": [
    "Первый абзац слишком длинный, разбейте на два предложения.",
    "Добавьте 1-2 тематических хештега в самый конец.",
    "Призыв к действию (CTA) выглядит слабым, сделайте его более вовлекающим."
  ]
}
```

## 4. Логика работы
1. **Trigger**: Получение задачи из очереди `QueueName.SEO`.
2. **Analysis Checklist**:
   - **Hook**: Привлекает ли первая строка внимание? Нет ли клише?
   - **Structure**: Читается ли текст "по диагонали"? Достаточно ли абзацев и пустого пространства? (В LinkedIn длинные стены текста не читают).
   - **Length**: Подходит ли текст под лимиты LinkedIn (до 3000 символов)?
   - **CTA**: Есть ли четкий призыв к действию или вопрос в конце?
3. **LLM Audit**:
   - LLM оценивает текст по этим критериям и формирует список конструктивных замечаний (`recommendations`).
   - Если оценка `score` ниже установленного порога (например, < 80), оркестратор Open Claw может вернуть текст обратно к Writing Agent вместе с рекомендациями SEO-агента для доработки.
4. **Publish**: Результат упаковывается и отправляется в `eventsQueue`.
